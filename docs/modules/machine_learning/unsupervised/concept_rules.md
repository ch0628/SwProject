# 비지도학습 프로토타입 규칙 및 State 설계

## 1. 문서 목적

이 문서는 SWfestival 공모전용 AI 학습 게이미피케이션 웹의 **머신러닝 - 비지도학습 프로토타입 규칙과 State 설계**를 기록한다.

이번 프로토타입의 목적은 다음과 같다.

1. 설계한 핵심 상호작용을 웹 브라우저에서 무리 없이 구현할 수 있는지 확인한다.
2. 상호작용 자체가 초등학생에게 재미있는지 확인한다.
3. 플레이 후 사용자가 비지도학습의 핵심 개념을 직관적으로 이해할 수 있는지 확인한다.

그래픽 완성도보다 **홀로그램 스캔 → 특징 조절 → 군집 변화 → 그룹 분석**이라는 핵심 상호작용을 우선한다.

---

## 2. 핵심 학습 목표

플레이 후 아이가 알아야 하는 핵심 개념은 하나로 고정한다.

> **정답을 알려주지 않아도 AI가 비슷한 것끼리 찾아 묶을 수 있다.**

게임 중에는 `군집화`, `feature`, `cluster` 등의 전문 용어를 먼저 강요하지 않는다.

플레이가 끝난 뒤 다음과 같이 연결한다.

> 아무도 정답을 알려주지 않았는데도 AI가 비슷한 특징을 가진 것들을 스스로 묶었어.  
> 이렇게 정답 없이 비슷한 것끼리 찾아 묶는 방법을 **비지도학습**이라고 해!

---

## 3. 지도학습에서 이어지는 스토리

지도학습 미션에서 CCTV AI를 다시 학습시키는 동안 도시에는 정체를 확인하지 못한 많은 인물이 들어왔다.

한 명씩 추적하고 조사하기에는 대상이 너무 많다.

따라서 관제센터는 먼저 현재 CCTV에 잡힌 인물들의 데이터를 한 번에 스캔하고, 비슷한 특징을 가진 인물들이 어떤 식으로 모이는지 AI에게 분석하게 한다.

중요:

- 이번 미션의 목표는 이미 존재하는 특정 조직명을 맞히는 것이 아니다.
- 처음부터 `A조직`, `B조직`, `C조직`이라는 정답 라벨이 존재하는 것으로 표현하지 않는다.
- AI는 정답을 전달받지 않은 상태에서 인물들의 특징을 비교하여 **숨겨진 패턴과 그룹 구조를 발견**한다.
- 어떤 그룹이 만들어졌다고 해서 그 그룹 전체를 악당이라고 단정하지 않는다.

---

## 4. 캐릭터 세계관

- 전체 서비스와 동일하게 사람의 형태를 한 귀여운 동물 캐릭터 세계관을 사용한다.
- 특정 동물 종 자체가 특정 집단이나 범죄 여부를 결정하지 않는다.
- 동물 세계관은 체격, 무게, 장비, 이동 속도 등 특징 차이를 시각적으로 과장해서 보여주기 위한 장치로 사용한다.

---

## 5. CCTV 스캔과 홀로그램 데이터 생성

### 5.1 실제 도시와 분석 공간 분리

광장 등 실제 CCTV 화면에서는 동물 캐릭터들이 계속 움직인다.

사용자가 `홀로그램 분석 시작 / SCAN`을 누르는 순간:

1. 현재 선택된 CCTV 화면 안에 존재하는 캐릭터를 확인한다.
2. 해당 시점의 분석용 특징 데이터를 복사한다.
3. 별도의 홀로그램 분석 공간에 캐릭터의 데이터 사본을 생성한다.

실제 도시의 원본 캐릭터는 스캔 이후에도 계속 이동한다.

홀로그램 분석 공간에 생성되는 것은 실제 캐릭터가 아니라 **스캔 시점의 데이터 복제본**이다.

따라서 홀로그램 분석 공간에서는 캐릭터가 고정되어 있거나 분석용 애니메이션만 수행해도 세계관상 문제가 없다.

### 5.2 프로토타입 기본 범위

한 번의 분석 라운드는 **현재 선택한 CCTV 화면의 스냅샷 데이터**를 기준으로 한다.

여러 CCTV의 스캔 데이터를 하나의 데이터셋으로 계속 합치는 기능은 프로토타입 필수 범위로 두지 않는다.

---

## 6. 분석 특징 다이얼

프로토타입에서는 특징을 세 개로 고정한다.

1. **체격·무게**
2. **장비 신호**
3. **이동 속도**

열화상, 이동 패턴, 통신 신호 등은 향후 확장 후보로 둔다.

---

## 7. 다이얼 단계

각 다이얼은 0~100의 연속 값으로 세밀하게 조절하지 않는다.

초등학생이 숫자 최적화 퍼즐을 풀게 되는 것을 막기 위해 **사용자 조작 단계는 3단계**로 고정한다.

표시 예:

- **안 봄**: 이번 분석에서 해당 정보를 사용하지 않음
- **조금 봄**: 해당 정보를 참고함
- **많이 봄**: 해당 정보를 중요하게 참고함

3개의 다이얼이 각각 3단계이므로 사용자가 만들 수 있는 설정 조합은 총 27가지이다. 다만 **27개의 설정이 반드시 27개의 서로 다른 군집 결과를 의미하지는 않는다.** 실제 군집 결과는 스캔된 캐릭터 데이터와 선택한 특징의 중요도에 따라 달라진다. 서로 다른 설정이 유사한 군집 결과를 만들 수도 있다.

중요:

- 27개의 결과 장면을 하나씩 수작업으로 만들지 않는다.
- 특정 다이얼 조합 하나만 정답으로 만들지 않는다.
- `안 봄 / 조금 봄 / 많이 봄`을 실제 군집 계산에 어떤 수치나 방식으로 반영할지는 **기술 설계 단계에서 결정한다.** 현재 문서에서는 UI와 의미만 확정한다.
- 세 다이얼이 모두 `안 봄`이면 분석에 사용할 정보가 없으므로 군집화를 진행하지 않고, "아무 정보도 보고 있지 않아 비슷한 친구를 찾을 수 없어!"와 같은 피드백을 제공한다.

---

## 8. 다이얼의 의미

다이얼의 의미는 다음과 같다.

> **AI가 이 정보를 얼마나 중요하게 살펴볼까?**

예:

- 이동 속도를 많이 보면 이동 속도가 비슷한 캐릭터끼리 더 가까워질 수 있다.
- 장비 신호를 많이 보면 장비 신호가 다른 캐릭터가 기존 그룹에서 분리될 수 있다.
- 체격·무게를 안 보면 체격 차이는 그룹 형성에 거의 영향을 주지 않는다.

사용자가 다이얼을 변경하면 홀로그램 군집 구조도 실시간 또는 짧은 재분석 연출 후 변화한다.

---

## 9. 여러 군집 결과 허용

비지도학습에는 하나의 정답 다이얼 조합을 만들지 않는다.

예:

- 이동 속도를 많이 보면 빠른 그룹 / 느린 그룹이 두드러질 수 있다.
- 장비 신호를 많이 보면 장비가 비슷한 캐릭터끼리 묶일 수 있다.
- 여러 특징을 함께 보면 더 복합적인 그룹이 나타날 수 있다.

핵심은:

> **무엇을 비슷하다고 볼지에 따라 보이는 패턴도 달라질 수 있다.**

---

## 10. 홀로그램 플랫폼 / 발판 생성

분석 시작 직후부터 모든 캐릭터를 미리 발판에 세워놓지 않는다.

초기에는 홀로그램들이 하나의 분석 공간에 뒤섞여 있다.

AI가 패턴을 찾기 시작하면:

1. 그룹이 형성될 위치에 홀로그램 플랫폼 또는 원형 영역이 생성된다.
2. 비슷한 캐릭터들이 해당 영역으로 이동한다.
3. 다이얼이 변경되면 일부 플랫폼이 합쳐지거나 갈라질 수 있다.
4. 캐릭터들도 새로운 분석 결과에 따라 다른 플랫폼으로 이동할 수 있다.

이 과정에서 많은 캐릭터가 자석처럼 촥촥 갈라지는 시각적 재미를 살린다.

---

## 11. 애매한 캐릭터

어떤 캐릭터는 특정 그룹 하나보다 **두 개 이상의 그룹과 비슷한 특징을 동시에 가질 수 있다.** 두 그룹 사이에서 애매할 수도 있고, 세 그룹 이상과 비슷한 정도가 비슷할 수도 있다.

이 경우 해당 캐릭터를 억지로 어느 한쪽 플랫폼에 넣지 않는다. 여러 그룹의 중앙에 별도의 **애매 영역**을 두고 해당 캐릭터를 그곳에 배치한다.

예:

```text
              GROUP A
              🐰 🐱

                 ↘
                  🦊
              애매 영역
               ↙   ↘

GROUP B                     GROUP C
🐻 🐺                       🐶 🐯
```

필요하면 애매한 캐릭터와 비슷한 여러 그룹 사이에 연결선이나 방향 표시를 보여줄 수 있다.

다이얼 설정이 변경되면:

- 애매 영역에 있던 캐릭터가 특정 그룹으로 이동할 수 있다.
- 기존 그룹에 있던 캐릭터가 다시 애매 영역으로 나올 수 있다.
- 어떤 캐릭터는 두 그룹이 아니라 세 그룹 이상과 동시에 비슷한 상태가 될 수 있다.

중요:

- 애매 영역은 `기타 그룹`이나 하나의 새로운 군집이 아니다.
- 이것을 `군집 실패`라고 표현하지 않는다.
- AI가 틀렸다고 표현하지 않는다.
- 기존의 `잘못된 군집이면 캐릭터끼리 싸운다`는 아이디어는 사용하지 않는다.

---

## 12. 정확도 표시 금지

비지도학습에는 정답 그룹이 없으므로 지도학습처럼 `정확도 90%`를 보여주지 않는다.

사용자에게 수치 정확도를 표시하지 않는다.

대신 필요하다면 다음과 같은 질적 표현을 사용한다.

- 패턴이 아직 흐릿해요
- 비슷한 특징이 보이기 시작해요
- 뚜렷한 그룹이 발견됐어요

`패턴 선명도 82%` 같은 숫자도 프로토타입 UI에서는 사용하지 않는다.

---

## 13. 그룹 분석 결과

사용자가 형성된 그룹을 선택하면 AI가 해당 그룹의 공통 특징을 설명한다.

예:

```text
GROUP B

- 이동 속도가 빠른 경우가 많음
- 장비 신호가 강함
- 체격은 비교적 다양함
```

초기에는 `GROUP A`, `GROUP B`, `GROUP C`처럼 중립적인 이름을 사용한다.

공통 특징 분석 이후 AI가 재미있는 임시 코드명을 붙일 수 있다.

예:

- 번개발 그룹
- 철가방 그룹

중요:

- 처음부터 범죄 조직 이름을 붙이지 않는다.
- 외모나 종족을 조롱하는 이름을 사용하지 않는다.
- 그룹명은 분석 결과 뒤에 붙인다.

---

## 14. 프로토타입 성공 조건

특정 다이얼 조합 하나를 맞히는 것을 성공 조건으로 두지 않는다.

사용자는 다이얼 설정을 바꾸어 보면서 **서로 다른 군집 패턴을 여러 개 직접 발견하고 분석**한다.

초기 프로토타입 기준으로는 약 3개의 서로 다른 패턴 발견을 목표값으로 둘 수 있으며, 정확한 수치는 플레이 테스트 후 조정한다.

같은 군집 결과를 다이얼만 조금 바꿔 반복 생성하는 것은 새로운 패턴으로 중복 카운트하지 않도록 한다.

---

## 15. 강화학습으로 연결되는 실제 사건

비지도학습 결과만으로 특정 그룹을 악당이라고 확정하지 않는다.

패턴 분석을 마친 뒤 실제 도시에서 사건이 발생한다.

연결 흐름:

```text
정체불명 인물 대규모 유입
↓
비지도학습으로 여러 행동/특징 패턴 발견
↓
특정 그룹 일부가 비슷한 방향으로 이동하는 모습 포착
↓
관제센터 경보
↓
여러 CCTV 장면이 빠르게 전환
↓
해당 인물 일부가 도시의 중요 시설에 집결
↓
실제 건물 점거 사건 발생
↓
이제 실제 사건을 통해 악당 여부가 확인됨
↓
다음 강화학습 스테이지로 연결
```

중요:

- `군집화 결과 = 악당`이 아니다.
- 비지도학습은 조사할 만한 패턴을 발견했을 뿐이다.
- 실제 사건이 발생한 뒤에야 일부 대상이 악당임이 확인된다.

### 컷신 방식

별도 MP4 영상보다는 기존 게임 캐릭터, 배경, CCTV UI를 재사용하는 **scripted cutscene**을 우선한다.

여러 짧은 장면을 붙여 생동감을 준다.

예:

1. 분석 완료
2. 관제센터 경보 발생
3. CCTV 1: 특정 인물들이 같은 방향으로 이동
4. CCTV 2: 건물 주변 집결
5. CCTV 3: 출입구 장악
6. 건물 내부/외부 CCTV: 점거 확인
7. 관제센터가 다음 대응 단계로 전환

점거 대상이 될 정확한 중요 시설의 종류는 강화학습 스토리 설계에서 확정한다.

```text
지도학습 미션 진행 중 정체불명 인물이 대량 유입
↓
한 명씩 조사하기에는 너무 많음
↓
사용자가 현재 CCTV 화면을 SCAN
↓
현재 화면에 보이는 캐릭터의 데이터 사본 생성
↓
홀로그램 분석 공간으로 이동
↓
홀로그램들이 한 공간에 뒤섞임
↓
사용자가 3개의 특징 다이얼 조절
[체격·무게 / 장비 신호 / 이동 속도]
↓
AI가 현재 선택된 특징 중요도를 기준으로 유사도를 분석
↓
그룹 플랫폼 생성
↓
비슷한 캐릭터들이 각 플랫폼으로 이동
↓
애매한 대상은 별도 경계 영역에 남음
↓
다이얼 변경
↓
일부 그룹이 합쳐지거나 갈라짐
↓
서로 다른 패턴 발견
↓
그룹 선택
↓
공통 특징 분석
↓
AI가 임시 코드명 부여
↓
필요한 수의 패턴 발견
↓
분석 결과 요약
↓
관제센터 경보
↓
여러 CCTV 컷신
↓
실제 건물 점거 사건 발생
↓
다음 강화학습 스테이지로 연결
```

---

# 17. 비지도학습 Game State

비지도학습의 메인 진행은 다음 State로 구성한다.

```text
INTRO
↓
SCAN_CAPTURE
↓
HOLOGRAM_SETUP
↓
FEATURE_EXPLORATION
↓
GROUP_ANALYSIS
↓
PATTERN_SUMMARY
↓
INCIDENT_CUTSCENE
↓
COMPLETE
```

---

## 17.1 INTRO

지도학습 스토리에서 자연스럽게 이어진다.

상황:

> CCTV AI를 다시 학습시키는 동안 도시로 정체를 확인하지 못한 인물이 너무 많이 들어왔다.  
> 한 명씩 조사하기에는 너무 많으므로 먼저 비슷한 특징을 가진 사람들이 있는지 AI에게 찾아보게 한다.

전이:

```text
INTRO
→ 분석 시작
→ SCAN_CAPTURE
```

---

## 17.2 SCAN_CAPTURE

사용자가 실제 CCTV 화면에서 분석 대상을 확보하는 단계이다.

사용자 행동:

- 분석할 CCTV 확인
- 현재 화면에 움직이는 캐릭터 관찰
- `SCAN / 홀로그램 분석 시작` 실행

SCAN 순간:

- 현재 CCTV 화면에 잡혀 있는 캐릭터 목록을 확정한다.
- 해당 캐릭터들의 분석용 특징값을 복사한다.
- 원본 캐릭터는 실제 도시에서 계속 이동한다.

전이:

```text
SCAN_CAPTURE
→ 스캔 완료
→ HOLOGRAM_SETUP
```

---

## 17.3 HOLOGRAM_SETUP

스캔된 데이터 사본을 홀로그램 분석 공간에 배치하는 짧은 전환 State이다.

연출:

```text
CCTV SCAN
↓
데이터 추출
↓
홀로그램 캐릭터 생성
↓
분석 공간에 뒤섞여 배치
```

아직 그룹 플랫폼은 생성하지 않는다.

세 개의 다이얼을 사용자에게 보여준다.

초기 다이얼 설정값은 구현 단계에서 정한다.

전이:

```text
HOLOGRAM_SETUP
→ 배치 완료
→ FEATURE_EXPLORATION
```

---

## 17.4 FEATURE_EXPLORATION

비지도학습의 핵심 플레이 State이다.

사용자는 다음 세 다이얼을 조정한다.

- 체격·무게
- 장비 신호
- 이동 속도

각 다이얼:

```text
안 봄 / 조금 봄 / 많이 봄
```

사용자가 설정을 변경하면:

1. 현재 설정값을 기준으로 캐릭터 유사도를 다시 계산한다.
2. 홀로그램 캐릭터가 이동한다.
3. 그룹 플랫폼이 생성 / 유지 / 분리 / 병합된다.
4. 애매한 캐릭터는 경계 영역에 배치된다.
5. 기존과 다른 의미 있는 패턴이 발견되면 기록할 수 있다.

중요:

- 이 State에는 하나의 정답 조합이 없다.
- 사용자는 여러 설정을 직접 실험한다.
- 모든 27개 조합을 반드시 시도할 필요는 없다.

전이:

```text
FEATURE_EXPLORATION
→ 분석하고 싶은 의미 있는 그룹 패턴 선택
→ GROUP_ANALYSIS
```

그룹 분석 후 다시 `FEATURE_EXPLORATION`으로 돌아와 다른 설정을 탐색할 수 있다.

---

## 17.5 GROUP_ANALYSIS

현재 발견된 군집 구조를 자세히 보는 State이다.

사용자는 특정 그룹을 선택한다.

AI가 다음 정보를 보여준다.

- 그룹의 공통적인 체격·무게 특징
- 장비 신호 특징
- 이동 속도 특징
- 특징이 일정하지 않은 항목

처음에는 `GROUP A / B / C ...`와 같은 중립적 이름을 사용한다.

공통 특징 분석 후 AI가 임시 코드명을 붙일 수 있다.

예:

```text
GROUP B

이동 속도: 빠른 편
장비 신호: 강한 편
체격·무게: 다양함

AI 임시 코드명:
"번개발 그룹"
```

분석 완료 후 두 방향이 가능하다.

```text
GROUP_ANALYSIS
→ 다른 패턴 탐색
→ FEATURE_EXPLORATION
```

또는 충분한 수의 서로 다른 패턴을 발견했다면:

```text
GROUP_ANALYSIS
→ PATTERN_SUMMARY
```

---

## 17.6 PATTERN_SUMMARY

사용자가 지금까지 발견한 서로 다른 군집 패턴을 간단하게 정리한다.

목적:

- 하나의 정답만 존재하지 않았다는 것을 보여줌
- 어떤 정보를 중요하게 보느냐에 따라 서로 다른 패턴이 나타날 수 있음을 체감하게 함

예:

```text
발견한 패턴

1. 이동 속도를 중심으로 본 그룹
2. 장비 신호를 중심으로 본 그룹
3. 여러 특징을 함께 본 그룹
```

여기에서도 정확도 점수를 사용하지 않는다.

전이:

```text
PATTERN_SUMMARY
→ 분석 완료
→ INCIDENT_CUTSCENE
```

---

## 17.7 INCIDENT_CUTSCENE

비지도학습에서 다음 강화학습 스테이지로 연결하기 위한 스토리 State이다.

여러 짧은 CCTV 장면을 이어 붙이는 scripted cutscene 형태를 사용한다.

흐름:

```text
분석 종료
↓
관제센터 경보
↓
특정 인물들의 비슷한 이동 포착
↓
여러 CCTV 자동 전환
↓
도시 중요 시설 주변에 집결
↓
실제 건물 점거 사건 발생
```

중요:

- 방금 발견한 그룹 전체가 악당이었다고 표현하지 않는다.
- 분석된 인물 중 일부가 실제 사건을 일으키는 장면을 통해 악당임이 확인된다.
- 군집화는 사건의 정답을 알려준 것이 아니라 패턴을 발견하는 데 도움을 준 것으로 표현한다.

전이:

```text
INCIDENT_CUTSCENE
→ 점거 사건 확인
→ COMPLETE
```

---

## 17.8 COMPLETE

비지도학습의 핵심 개념을 짧게 설명한다.

예:

> 아무도 정답을 알려주지 않았는데도 AI가 비슷한 특징을 가진 것들을 스스로 묶었어.  
> 이렇게 정답 없이 비슷한 것끼리 찾아 묶는 방법을 **비지도학습**이라고 해!

이후 건물 점거 사건 대응을 위해 다음 강화학습 스테이지로 연결한다.

---

# 18. 분석 데이터 State

스캔된 홀로그램 데이터는 실제 도시 캐릭터와 분리한다.

```text
AnalysisSnapshot
- id
- sourceCctvId
- capturedAt
- hologramCharacters[]
```

---

# 19. 홀로그램 캐릭터 State

최소 구조:

```text
HologramCharacter

Identity
- snapshotCharacterId
- sourceCharacterId

Features
- bodyWeight
- equipmentSignal
- moveSpeed

Clustering
- currentGroupId
- ambiguity
```

정확한 수치 범위와 계산 방식은 구현 단계에서 정한다.

---

# 20. 다이얼 State

```text
FeatureLevels

- bodyWeightLevel
- equipmentSignalLevel
- moveSpeedLevel
```

각 값은 프로토타입에서 세 단계 중 하나이다.

```text
NONE
LOW
HIGH
```

UI 표시:

```text
안 봄
조금 봄
많이 봄
```

이 State는 사용자가 선택한 **특징 중요도 단계**만 저장한다. `NONE / LOW / HIGH`를 실제 군집 계산에서 어떤 수치 또는 방식으로 반영할지는 기술 설계 단계에서 결정하며, 현재 문서에서는 특정 수치 매핑을 확정하지 않는다.

---

# 21. 군집 / 그룹 State

```text
ClusterGroup

- id
- members[]
- summary
- temporaryName
```

플랫폼 위치, 애니메이션 좌표 등은 구현 단계의 렌더링 데이터이므로 현재 규칙 문서에서 고정하지 않는다.

---

# 22. 별도 저장하지 않는 계산 상태

다음과 같은 정보는 가능하면 원본 데이터에서 계산한다.

```text
isAmbiguous
isPatternClear
isNewPattern
```

- `isAmbiguous`: 여러 그룹과의 유사도가 비슷한지 계산
- `isPatternClear`: 현재 군집 구조가 사용자에게 보여줄 만큼 뚜렷한지 내부 기준으로 계산
- `isNewPattern`: 이미 발견한 군집 구조와 충분히 다른지 비교

불필요한 boolean 상태를 중복 저장하지 않는다.

---

# 23. State 설계 핵심 원칙

### 23.1 실제 도시와 홀로그램 분석 데이터를 분리한다

실제 도시 캐릭터는 계속 움직인다.

홀로그램은 스캔 순간의 분석용 데이터 사본이다.

### 23.2 다이얼 조절은 군집 결과를 실제로 변화시킨다

다이얼은 단순 장식 UI가 아니다.

다이얼 단계가 실제 군집 계산에 영향을 주어야 한다. 구체적인 수치 매핑 방식은 기술 설계 단계에서 결정한다.

### 23.3 하나의 정답 군집을 만들지 않는다

특정 다이얼 조합을 맞혀야만 성공하는 퍼즐로 만들지 않는다.

### 23.4 애매한 캐릭터를 실패로 처리하지 않는다

경계에 있는 캐릭터는 별도 공간에 표시하며, 잘못된 군집이나 오답으로 표현하지 않는다.

### 23.5 군집 결과와 범죄 여부를 동일시하지 않는다

AI가 비슷한 특징의 그룹을 발견한 것과 악당 여부를 판단하는 것은 별개이다.

악당 여부는 이후 실제 사건을 통해 확인한다.

---

# 24. 수치 및 구현 단계에서 조정할 항목

- 한 번의 SCAN에 포함되는 캐릭터 수
- 한 화면에서 동시에 보여줄 홀로그램 수
- 군집 개수
- 그룹 플랫폼 개수
- 애매 영역 판정 기준
- `isPatternClear` 내부 기준
- 서로 다른 패턴으로 인정하는 기준
- 완료에 필요한 패턴 수 (초기 후보: 약 3개)
- 다이얼 변경 후 재군집 애니메이션 시간
- 플랫폼 생성 / 병합 / 분리 애니메이션 속도
- 그룹 임시 코드명
- INCIDENT_CUTSCENE 길이
- 점거 대상이 되는 중요 시설의 종류

---

# 25. 이번 프로토타입에서 제외하거나 이후 확장할 요소

- 4개 이상의 특징 다이얼
- 열화상
- 이동 패턴
- 통신 신호
- 여러 CCTV 스캔 데이터의 복합 병합 분석
- 전문적인 군집 평가 지표 노출
- 정답 정확도 표시
- 군집 실패 시 캐릭터끼리 싸우는 연출
- 특정 동물 종과 특정 조직을 고정적으로 연결하는 설정

# 26. 비지도학습 State 설계 완료 상태

현재 비지도학습에 대해서는 다음 수준까지 설계가 완료되었다.

- 핵심 학습 목표
- 지도학습에서 이어지는 스토리
- 현재 CCTV 화면 스캔 방식
- 실제 캐릭터와 홀로그램 데이터 분리
- 특징 다이얼 3개
- 다이얼 3단계
- 다이얼 가중치에 따른 군집 변화 원칙
- 여러 군집 결과 허용
- 홀로그램 플랫폼 생성
- 애매한 캐릭터 처리
- 정확도 수치 미사용
- 그룹 분석 및 임시 코드명
- 패턴 탐색형 완료 방식
- 건물 점거 사건으로 이어지는 컷신
- 메인 Game State
- 분석 데이터 State
- 홀로그램 캐릭터 State
- 다이얼 State
- 그룹 State
- 중복 상태 제거 원칙

다음 단계는 **강화학습의 세부 규칙 설계**이다.

# Reward Redesign v2 검증 보고서

검증일: 2026-10-15  
결론: **합계 8개의 사용자 별 4종 + 고정 목표 보상 3 + 점진형 매핑 B를 적용한다.**

## 1. 새 Reward 설계 요약

- `goal`은 사용자가 고르는 별에서 제거하고 내부 고정 보상 `3`으로 둔다.
- 사용자는 네 항목에 별을 정확히 8개 나눈다.
- 각 항목은 정수 `0~3`개다.
- 별은 내부 학습 가중치로 `0 → 0`, `1 → 1`, `2 → 2.5`, `3 → 5`로 변환한다.
- 기존 reward normalization, 5 Round × 5 Robot 학습, Round 종료 뒤 1회 정책 갱신, 최종 정책 고정 평가는 유지한다.

## 2. 사용자에게 보여 주는 별 항목

| 필드 | 화면 의미 | 직접 영향을 확인한 대표 행동/지표 |
|---|---|---|
| `speed` | 빠르게 해결하기 | 논리 시간, TIMEOUT, `FAST_PASS`, `SUBDUE`, `RETREAT` |
| `facilityDamage` | 시설 보호 | 시설 손상, `PUSH`, `CLEAR`, `DETOUR` |
| `citizenRisk` | 시민 보호 | 시민 위험, `FAST_PASS`, `WAIT`, `WIDE_DETOUR` |
| `citizenMisunderstanding` | 시민을 정확히 판단하기 | 오판 종료, `SUBDUE`, `OBSERVE`, `TRACK`, `BYPASS` |

`goal`은 언제나 적용되지만 사용자 항목도, 별 budget도 아니다.

## 3. 별 배분 규칙

최종 규칙은 **최대 8개가 아니라 정확히 8개**다.

1. 네 항목 각각 `0, 1, 2, 3`만 허용한다.
2. 네 값의 합은 반드시 `8`이어야 한다.
3. 조건을 만족하는 조합은 정확히 `31개`다.
4. 합계가 8이 아니거나, 필드가 네 개가 아니거나, 범위를 벗어나면 학습 시작 전에 거부한다.

정확히 8개를 택한 이유는 초등학생에게 “별 8개를 네 곳에 모두 나눠 준다”라고 설명할 수 있고, 별을 남겼을 때 전체 reward 크기까지 달라지는 추가 개념을 없애기 위해서다. 기본값은 `(2, 2, 2, 2)`다.

## 4. 내부 매핑 규칙

선택한 매핑은 후보 B다.

| 사용자 별 | 내부 가중치 |
|---:|---:|
| 0 | 0 |
| 1 | 1 |
| 2 | 2.5 |
| 3 | 5 |

고정 `goal` 가중치는 기존값 `3`을 유지한다. 목표 보상 2/3/4 민감도 비교에서 후보 B의 평균 성공률은 각각 `41.73% / 41.85% / 42.13%`였고, 다른 핵심 지표 변화도 작았다. 4로 높여 얻는 성공률 차이가 `0.28%p`에 불과해 기존값을 바꿀 근거가 부족했다.

## 5. 후보 A/B/C 비교

실험 조건:

- 후보 A: `[0, 1, 2, 3]`
- 후보 B: `[0, 1, 2.5, 5]`
- 후보 C: `[0, 1, 3, 6]`
- Training seed `1~10`
- 각 설정마다 `5 Round × 5 Robot`
- 각 최종 정책마다 Evaluation seed `10001~10020`, 총 20 Episode
- Evaluation 동안 정책 update `0회`
- 직접 marginal 13조합과 합계 8의 31조합을 분리
- 목표 보상 2/3/4 민감도 포함
- 총 실험 행 `318`, 총 headless episode `143,150`

모든 후보가 네 목표 지표에서 0→1→2→3 단조 방향을 만족했다. 차이는 높은 별의 분리 정도였다.

| 항목 | A의 2→3 직접 변화 | B의 2→3 직접 변화 | C의 2→3 직접 변화 |
|---|---:|---:|---:|
| 평균 논리 시간 | -3.59 | -8.07 | -12.62 |
| 시설 손상/Episode | -0.010 | -0.030 | -0.030 |
| 시민 위험/Episode | -0.020 | -0.025 | -0.015 |
| 오판 종료율 | -1.5%p | -2.0%p | -2.0%p |

- A는 가장 높은 평균 성공률(`42.66%`)을 보였지만 2단계와 3단계가 다시 붙는 문제가 남았다.
- C는 속도 구분이 가장 강했지만 시민 위험의 2→3 구분이 B보다 작고, 합계 8 전체 평균 성공률도 가장 낮았다(`41.60%`).
- B는 네 항목 모두 높은 단계 차이를 유지하면서 평균 성공률 `41.85%`로 C보다 높았다. 따라서 B를 선택했다.

## 6. 별 단계별 행동 분리 결과

합계 8인 31조합에서 해당 별 수준별 평균을 비교했다. 나머지 별은 합계 8을 유지하므로 순수 단일 변수 효과가 아니라 실제 사용자가 만드는 trade-off를 포함한다.

| 별 항목 | 0개 | 1개 | 2개 | 3개 | 0→3 변화 |
|---|---:|---:|---:|---:|---:|
| `speed`: 평균 논리 시간 | 582.56 | 404.44 | 390.85 | 383.85 | -198.71 (-34.1%) |
| `facilityDamage`: 손상/Episode | 0.473 | 0.322 | 0.242 | 0.187 | -60.6% |
| `citizenRisk`: 위험/Episode | 0.487 | 0.372 | 0.257 | 0.150 | -69.3% |
| `citizenMisunderstanding`: 오판 종료율 | 28.5% | 26.7% | 23.6% | 18.5% | -10.0%p |

동일한 합계 8 안에서 한 항목을 +1하고 다른 항목을 -1한 matched comparison도 모든 단계에서 의도한 방향이었다.

- `speed` 시간 변화: `-178.67`, `-12.85`, `-6.98`
- `facilityDamage` 손상 변화: `-0.150`, `-0.082`, `-0.055`
- `citizenRisk` 위험 변화: `-0.104`, `-0.114`, `-0.109`
- `citizenMisunderstanding` 오판 종료율 변화: `-1.44%p`, `-3.39%p`, `-5.07%p`

즉, “별이 많으면 그 행동 기준을 더 중요하게 배운다”는 설명이 네 항목 모두에서 관찰된다.

## 7. 극단 조합 행동 요약

후보 B, 목표 보상 3, 합계 8 조합의 0별과 3별 평균이다.

- 속도 0→3: `FAST_PASS 6.3%→34.8%`, `SUBDUE 27.3%→50.7%`, `RETREAT 22.8%→5.9%`; 성공률은 `19.3%→42.6%`, 시간은 `582.56→383.85`였다.
- 시설 보호 0→3: `PUSH 74.5%→35.1%`, `CLEAR 19.8%→43.1%`, `DETOUR 5.7%→21.8%`; 손상은 `0.473→0.187`이었다.
- 시민 보호 0→3: `FAST_PASS 44.2%→12.5%`, `WAIT 24.3%→31.7%`, `WIDE_DETOUR 10.0%→26.5%`; 위험은 `0.487→0.150`이었다.
- 정확한 판단 0→3: `SUBDUE 59.0%→40.1%`, `OBSERVE 15.6%→26.1%`, `TRACK 14.4%→25.1%`; 오판 종료율은 `28.5%→18.5%`였다.

행동이 의도대로 크게 달라지지만 높은 별에서 어느 한 행동이 거의 100%로 고정되는 현상은 없었다. 다만 속도 0은 TIMEOUT과 낮은 성공률을 크게 늘린다. 이는 명시적으로 속도를 중요하지 않다고 정한 결과이지만, 수업 안내에서 trade-off로 설명할 필요가 있다.

## 8. 코드 반영 내역

- `RewardStars`를 네 사용자 필드로 분리했다.
- `goal`은 `FIXED_GOAL_REWARD_WEIGHT = 3`으로 고정했다.
- `REWARD_STAR_TOTAL = 8`, `REWARD_STAR_TO_WEIGHT = [0, 1, 2.5, 5]`를 단일 계약으로 추가했다.
- 사용자 입력은 네 필드, 정수 0~3, 합계 정확히 8인지 검증한 뒤 내부 `RewardWeights`로 변환한다.
- UI에서 `goal` 선택을 제거하고, 사용한 별 수를 표시하며 합계 8 전에는 시작 버튼을 비활성화한다.
- 학습 history에는 `selectedRewardStars` 네 값과 재현용 `resolvedRewardWeights`를 모두 저장한다.
- 기존 normalization과 학습/평가 알고리즘은 바꾸지 않았다.
- 기존 history는 메모리 안에서만 존재해 별도 영속 데이터 migration은 필요하지 않았다.

## 10. 남은 위험과 후속 과제

1. 200 evaluation episode/조합은 설계 선택에 충분한 방향성을 보였지만 통계적 신뢰구간을 계산한 임상적 수준의 검정은 아니다.
2. 별 0→1 효과는 여전히 가장 크다. B는 2→3을 살렸지만 네 단계가 완전히 등간격으로 느껴지지는 않는다.
3. 속도 0 조합은 성공률이 낮고 시간이 길다. 수업 문구에서 “느려도 안전하면 무조건 성공”이라고 오해하지 않도록 설명해야 한다.
4. Ari 문구와 시각적 별 배분 UX의 별도 완성도 작업은 이번 범위에서 하지 않았다. 데이터 계약과 유효성 검증만 최소 변경했다.

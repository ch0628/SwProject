# 강화학습 프로토타입 규칙 및 State 설계

## 1. 문서 목적

이 문서는 SWfestival 공모전용 AI 학습 게이미피케이션 웹의 **머신러닝 - 강화학습 프로토타입 규칙과 State 설계**를 기록한다.

이번 프로토타입의 목적은 다음과 같다.

1. 설계한 핵심 상호작용을 웹 브라우저에서 무리 없이 구현할 수 있는지 확인한다.
2. 상호작용 자체가 초등학생에게 재미있는지 확인한다.
3. 플레이 후 사용자가 강화학습의 핵심 개념을 직관적으로 이해할 수 있는지 확인한다.

실제 강화학습 알고리즘을 브라우저에서 학습시키는 것이 목적은 아니다.
대신 **병렬 시뮬레이션 + 보상/벌점 기반 행동 선택 규칙**을 이용하여 강화학습의 시행착오와 정책 개선 과정을 체험하도록 구현한다.

---

## 2. 핵심 학습 목표

플레이 후 아이가 알아야 하는 핵심 개념은 하나로 고정한다.

> **AI가 행동하고 받은 보상과 벌점을 이용해서 더 좋은 행동을 배운다.**

게임 중에는 `policy`, `reward function`, `episode` 등의 전문 용어를 먼저 사용하지 않는다.

플레이 종료 후 다음과 같이 연결한다.

> AI는 처음부터 어떻게 움직여야 하는지 알고 있었던 게 아니야.  
> 여러 행동을 직접 시도하고, 좋은 결과에는 보상을 받고 위험한 행동에는 벌점을 받으면서 더 좋은 행동을 배웠어.  
> 이렇게 행동의 결과를 이용해서 배우는 방법을 **강화학습**이라고 해!

---

## 3. 비지도학습에서 이어지는 스토리

비지도학습에서 여러 인물의 행동/특징 패턴을 분석한 뒤, 관제센터에 긴급 경보가 발생한다.

여러 CCTV 장면을 통해 일부 인물들이 도시의 중요 시설로 이동하고 실제 점거 사건을 일으키는 장면이 확인된다.

중요:
- 비지도학습에서 군집화했다고 해서 그 그룹 전체를 악당으로 확정하지 않는다.
- 실제 사건이 발생한 뒤에야 일부 대상이 악당임이 확인된다.
- 강화학습 스테이지는 이 점거 사건에 대응하는 과정으로 시작한다.

---

## 4. 점거 대상 건물

프로토타입에서는 **5층 규모의 도시 교통 관제센터**를 기본 대상으로 한다.

건물 내부에는 다음 요소가 존재한다.

- 일반 계단
- 비상계단
- 엘리베이터
- 여러 복도
- 좁은 통로
- 우회로
- 지름길
- 파손 가능한 시설물/장애물
- 대피 중인 시민
- 최종 목표인 5층 중앙 보안실

층별 선택지의 조합을 통해 목표까지 **약 20~25개 이상의 유효한 경로**가 생기도록 설계한다.

중요:
- AI에게 25개의 완성된 경로 중 하나를 고르게 하는 것이 아니다.
- 각 교차로와 상황에서 작은 행동을 선택하고, 그 선택들이 이어져 결과적으로 다양한 경로가 만들어진다.
- 하나의 절대적인 최적 경로만 정답으로 만들지 않는다.

---

## 5. 건물 내부 시민 설정

건물 내부에 일부 시민이 남아 있다.

이들은 **인질이 아니다.**

점거가 갑작스럽게 발생해 미처 대피하지 못한 직원/방문객이며, 일부는 출구나 안전구역으로 이동 중이다.

악당은 주로 상층부와 중앙 보안실을 장악한 상태로 설정한다.

시민은 강화학습에서 다음 역할을 한다.

- 보호해야 하는 대상
- AI가 안전한 행동을 선택해야 하는 이유
- `시민 위험` 벌점을 발생시키는 환경 요소

시민과 부딪히거나 지나치게 위험하게 접근했다고 해서 즉시 Episode가 종료되지는 않는다.
대신 벌점을 받아 이후 행동 선택에 영향을 준다.

---

## 6. 실전 투입 전 시뮬레이션

AI 대응 로봇을 바로 실제 건물에 투입하지 않는다.

관제센터가 실제 건물 구조와 CCTV 데이터를 이용해 **홀로그램 시뮬레이션 공간**을 만든다.

스토리 설명 예:

> 바로 AI를 보내면 시민과 시설이 위험할 수 있어!  
> 건물을 똑같이 복제해서 먼저 연습시키자!

실제 건물과 가상 훈련 공간의 기본 구조는 동일하게 유지한다.

프로토타입에서는 훈련 Round마다 건물 구조, 장애물 위치 등을 랜덤하게 크게 변경하지 않는다.

이유:
- 환경 변화와 AI 학습 효과가 섞이는 것을 방지한다.
- 아이가 “문제가 쉬워진 것”이 아니라 “AI 행동이 개선된 것”으로 이해하게 한다.

환경 랜덤화는 향후 확장 기능으로 둔다.

---

## 7. 사용자 역할

사용자가 AI 로봇을 직접 조종하거나 정답 경로를 그려주는 게임이 아니다.

사용자는:

> **AI가 어떤 결과를 좋은 행동이라고 생각해야 하는지 정한다.**

AI는 그 규칙을 바탕으로 스스로 여러 행동을 시도한다.

핵심 루프:

```text
사용자
보상 / 벌점 중요도 설정
↓
AI
여러 행동과 경로 시도
↓
환경
행동 결과 평가
↓
AI
보상 / 벌점 획득
↓
중앙 AI의 행동 선택 경향 변화
↓
다음 Round에서 새로운 행동 시도
```

---

## 8. 보상 / 벌점 항목

프로토타입에서는 4개 항목을 사용한다.

1. **목표 도달**
   - 5층 중앙 보안실에 도달하고 시스템을 복구하는 것을 얼마나 중요하게 생각할지

2. **빠른 해결**
   - 빠른 시간 안에 목표에 도달하는 것을 얼마나 중요하게 생각할지

3. **시설물 파손**
   - 벽, 장비, 가구 등 시설물을 파손하는 행동을 얼마나 강하게 싫어할지

4. **시민 위험**
   - 시민과 충돌하거나 위험하게 접근하는 행동을 얼마나 강하게 싫어할지

각 항목은 4단계로 조절한다.

```text
신경 안 씀
조금 중요
중요
매우 중요
```

숫자 점수는 사용자에게 직접 보여주지 않는다.

내부 구현에서는 필요하면 수치로 매핑할 수 있으나 정확한 점수 계산식은 구현 단계에서 결정한다.

---

## 9. 하나의 정답 조합은 없음

보상/벌점 설정에는 하나의 정답만 존재하지 않는다.

예:

### 빠른 해결형

- 빠른 시간에 목표 도달
- 일부 시설 파손
- 시민 위험은 낮음 또는 보통

### 안전형

- 시간이 더 오래 걸림
- 시설 파손 거의 없음
- 시민 위험 거의 없음

둘 다 목표를 달성할 수 있다.

게임이 특정 보상 설정 하나를 정답으로 강제하지 않는다.

사용자가 원하는 행동 성향을 직접 만들도록 한다.

---

## 10. 이상한 보상 규칙도 허용

사용자가 비정상적이거나 극단적인 보상 설정을 만드는 것을 막지 않는다.

예:

- 빠른 해결 매우 중요
- 시설물 파손 신경 안 씀

결과:
- 장애물을 밀어버리고 지름길로 빠르게 이동
- 목표에는 빨리 도달하지만 시설 피해가 큼

예:

- 시민 위험 매우 중요
- 빠른 해결 중요도 낮음

결과:
- 시민 근처에서 매우 조심함
- 안전하지만 시간이 오래 걸림

이 과정을 통해:

> **어떤 행동에 보상을 주느냐에 따라 AI의 행동도 달라진다.**

를 자연스럽게 체험하게 한다.

---

## 11. 중앙 AI와 연습 로봇 5대

훈련에는 **중앙 AI 1개**와 **병렬 연습 로봇 5대**를 사용한다.

구조:

```text
중앙 AI 정책 1개
     │
     ├─ 연습 복제본 #1
     ├─ 연습 복제본 #2
     ├─ 연습 복제본 #3
     ├─ 연습 복제본 #4
     └─ 연습 복제본 #5
```

5대는 서로 독립적으로 따로 학습하는 AI가 아니다.

**같은 중앙 AI의 현재 행동 선택 경향을 공유하는 병렬 훈련 복제본**이다.

아이에게는 다음과 같이 설명한다.

> 같은 AI의 연습 로봇 5대가 동시에 여러 방법을 시험하고 있어!

---

## 12. 병렬 경험 수집

한 Round에서 5개의 연습 로봇은 같은 중앙 AI 정책을 공유하지만 서로 다른 행동을 선택할 수 있다.

예:

```text
#1 → 비상계단
#2 → 엘리베이터
#3 → 좁은 지름길
#4 → 넓은 우회로
#5 → 정문 계단
```

각 로봇은 서로 다른 결과를 얻는다.

예:

```text
#1 → 목표 근처까지 도달 / 안전
#2 → 느림
#3 → 빠르지만 시설 파손
#4 → 안전하지만 시간 초과
#5 → 막다른 길
```

5개의 경험을 중앙 AI에 모아 다음 Round의 행동 선택 경향을 변경한다.

강화학습 체험에서 반드시 유지해야 하는 인과관계:

```text
행동
↓
결과
↓
보상 / 벌점
↓
행동 선택 경향 변화
↓
다음 행동
```

---

## 13. 훈련 횟수

프로토타입에서는:

```text
연습 로봇 5대
×
20 Round
=
총 100회 경험
```

으로 구성한다.

100개의 독립 AI가 학습하는 것이 아니다.

동일한 중앙 AI가 5개의 병렬 복제본을 이용해 빠르게 경험을 수집하는 구조이다.

---

## 14. 동일 조건의 5개 병렬 Simulation Instance

5개의 연습 로봇은 **동일한 5층 건물 Template과 동일한 기본 환경 조건을 가진 5개의 병렬 Simulation Instance**에서 각각 독립적으로 행동한다.

구조:

```text
Building Template
├─ Simulation #1 → Robot #1
├─ Simulation #2 → Robot #2
├─ Simulation #3 → Robot #3
├─ Simulation #4 → Robot #4
└─ Simulation #5 → Robot #5
```

각 Simulation의 기본 건물 구조, 장애물 조건, 시민 배치 등은 동일하게 유지한다.

중요:
- 연습 로봇끼리는 서로 물리적으로 영향을 주지 않는다.
- 다른 연습 로봇 때문에 길이 막히거나 점수가 떨어지는 일이 없어야 한다.
- 각 로봇의 결과는 자신의 행동 선택에 의해 결정되어야 한다.
- 5개 경험은 Round 종료 후 중앙 AI에 합쳐진다.

사용자 화면에서는 5개의 Simulation을 모두 별도 건물로 동시에 보여줄 필요가 없다.

### Main View
선택된 Simulation 하나만 실제 플레이 화면으로 렌더링한다.

### Mini View / Status
나머지 Simulation은 현재 층, 위치, 행동, 성공/실패 상태 등 요약 정보만 표시할 수 있다.

### Overview
5개 Simulation의 로봇 위치와 이동 경로를 **하나의 건물 지도 위에 합성해서 시각화**한다.

동일 위치나 같은 경로에 여러 로봇이 존재할 경우:
- 작은 위치 offset
- 묶음 표시 (`Robot ×3`)
- 경로선 분리
- 선택 시 개별 정보 표시

등을 이용해 시각적으로 겹쳐 보이는 문제를 방지한다.

이 구조를 통해 병렬 훈련의 의미는 유지하면서도 로봇끼리 서로 관통하거나 충돌하는 어색한 장면을 피한다.

---

## 15. 행동 선택 구조

실제 강화학습 모델이 행동을 생성하도록 하지 않는다.

프로토타입에서는 미리 충분한 **Action Template / 행동 Pool**을 만든다.

예:

### 이동 행동
- 가까운 계단 이용
- 먼 비상계단 이용
- 엘리베이터 이용
- 좁은 통로 진입
- 넓은 복도 우회
- 막다른 길 진입 후 복귀
- 지름길 시도

### 장애물 대응
- 장애물 우회
- 장애물 밀기
- 다른 통로 선택
- 잠시 대기
- 좁은 틈 통과

### 시민 대응
- 시민 뒤에서 기다림
- 크게 우회
- 천천히 통과
- 빠르게 통과
- 다른 통로 선택

### 목표 탐색
- 이전 성공 경로 일부 재사용
- 새로운 경로 탐색
- 높은 평가를 받은 방향 재시도
- 안전했던 경로 재사용

---

## 16. 행동 Pool 선택 원칙

단순히 전체 점수 하나만 보고 행동 Pool을 정하지 않는다.

행동 Pool은 다음 요소를 함께 고려한다.

```text
현재 상황
+
지금까지의 행동 평가
+
사용자가 설정한 보상 / 벌점 중요도
↓
사용 가능한 행동 Pool 구성
↓
그 안에서 확률적으로 행동 선택
```

예:

### 현재 상황: 시민이 앞을 막고 있음

시민 위험 벌점이 높다면:
- 기다리기 선택 확률 증가
- 우회 선택 확률 증가
- 위험하게 통과 선택 확률 감소

빠른 해결 보상이 높고 시민 위험 벌점이 낮다면:
- 빠르게 통과 선택 확률 증가

### 현재 상황: 장애물이 길을 막음

시설물 파손 벌점이 낮다면:
- 장애물 밀기 선택 확률 증가

시설물 파손 벌점이 높다면:
- 우회 선택 확률 증가

---

## 17. Round별 행동 변화

초반에는 탐색성이 높은 행동 Pool을 사용한다.

### Round 1~5
- 다양한 행동 시도
- 실패 많음
- 막다른 길
- 불필요한 우회
- 시설물 충돌
- 여러 경로 탐색

### Round 6~10
- 이전에 높은 평가를 받은 행동 선택 비중 증가
- 높은 층 진입 증가
- 일부 좋은 경로 발견

### Round 11~15
- 성공했던 행동 조합 재사용 증가
- 목표 도달 사례 증가
- 여전히 일부 새로운 행동 탐색

### Round 16~20
- 사용자 보상 설정에 맞는 행동 성향이 뚜렷해짐
- 여러 복제본이 비슷한 좋은 경로를 선택하는 모습이 나타날 수 있음

중요:
- 특정 Round에 반드시 성공하도록 고정하지 않는다.
- 사용자의 보상 설정이 극단적이면 마지막에도 이상한 행동 성향이 유지될 수 있다.

---

## 18. 한 번의 시도 종료 조건

연습 로봇 하나의 한 번의 시도는 다음 조건에서 종료한다.

### 성공
- 5층 중앙 보안실 도달
- 시스템 복구 성공

### 실패
- 제한 시간 초과
- 더 이상 이동 가능한 경로가 없음
- 누적 충돌로 연습 로봇 작동 불능

### 즉시 실패가 아닌 요소
- 시설물 파손
- 시민 위험
- 느린 이동

이러한 행동은 벌점을 받지만 Episode를 바로 종료하지 않는다.

따라서:

> 시설물을 많이 파손했지만 빠르게 목표에 도달

한 경우도 **성공했지만 낮거나 특정 성향의 평가를 받는 경험**이 될 수 있다.

---

## 19. 훈련 화면 구조

훈련 화면은 기본적으로:

```text
Main View 1개
+
Mini View / Status 4개
+
전체 건물 Overview
```

구조로 설계한다.

### Main View
사용자가 선택한 Simulation 하나만 실제 플레이 화면으로 렌더링한다.

### Mini View / Status
나머지 Simulation은 반드시 실시간 게임 화면을 렌더링할 필요가 없다.

다음 정도의 정보만 표시해도 된다.

- 현재 층
- 위치
- 현재 행동
- 성공 / 실패 상태
- 중요 이벤트
- 필요 시 간단한 썸네일

### Overview
5개 Simulation의 위치/경로 데이터를 하나의 5층 건물 지도 위에 합성하여 보여준다.

이 구조를 통해 5개의 전체 화면을 동시에 풀 렌더링하지 않고도 병렬 훈련 상황을 전달하며, PC 기준 60fps 목표에 유리한 구조를 유지한다.

정확한 렌더링 방식은 기술 스택 단계에서 결정한다.

---

## 20. View State

훈련 화면의 카메라 상태는 다음 세 가지 모드로 구분한다.

```text
AUTO
FOLLOW_ROBOT
OVERVIEW
```

### AUTO
사용자가 특정 로봇을 직접 선택하지 않은 상태.

시스템이 중요한 사건을 자동으로 Main View에 보여줄 수 있다.

### FOLLOW_ROBOT
사용자가 특정 로봇을 직접 선택한 상태.

예:

```text
selectedRobotId = #3
```

이 경우 시스템은 다른 로봇에서 사건이 발생해도 강제로 Main View를 전환하지 않는다.

### OVERVIEW
5층 건물 전체에서 다섯 연습 로봇의 위치와 이동을 한눈에 확인한다.

---

## 21. Micro Event

훈련 중 중요한 사건은 짧게 강조한다.

### 일반 사건
- 작은 충돌
- 일반적인 우회
- 막다른 길

처리:
- 짧은 효과
- 아이콘
- 상태 표시

### 강조할 사건
- 최초 3층 도달
- 최초 5층 도달
- 최초 목표 성공
- 새로운 최고 기록
- 새로운 경로 발견
- 대형 시설 파손
- 심각한 시민 위험

처리:
- Micro Cutscene
- 강조 UI
- 리플레이 후보 등록

---

## 22. 사용자 시점과 이벤트 충돌 규칙

사용자가 특정 로봇을 직접 보고 있는 경우 그 선택을 최우선으로 한다.

예:

사용자가 Robot #3을 FOLLOW 중인데 Robot #5가 최초 목표 도달.

시스템은 강제로 #5 화면으로 전환하지 않는다.

대신:

```text
🎯 #5 최초 목표 도달!
[보기]

💥 #2 대형 충돌
[보기]
```

처럼 알림을 제공한다.

사용자가 `[보기]`를 선택하면 짧은 리플레이를 보여준 뒤 기존 #3 Follow 화면으로 복귀한다.

AUTO 상태에서는 시스템이 주요 이벤트를 자동으로 Main View에 보여줄 수 있다.

---

## 23. Round 평가

한 Round의 5개 시도가 종료되면 각 경험을 평가한다.

예:

```text
#1
목표 성공
빠름
시설 파손 많음
시민 위험 있음

#2
목표 성공
느림
시설 파손 없음
시민 위험 없음

#3
시간 초과

#4
목표 성공
보통 속도
파손 적음

#5
작동 불능
```

사용자가 설정한 보상/벌점 중요도에 따라 같은 결과라도 평가가 달라질 수 있다.

---

## 24. 중앙 AI 업데이트

각 Round 종료 후 5개의 경험을 중앙 AI의 행동 선택 규칙에 반영한다.

실제 PPO, Q-learning 등의 강화학습 알고리즘을 사용하지 않는다.

대신:

- 높은 평가를 받은 행동 특징 → 다음 Round에서 선택 가능성 증가
- 낮은 평가를 받은 행동 특징 → 선택 가능성 감소
- 낮은 평가 행동도 완전히 제거하지 않음
- 일정 수준의 새로운 행동 탐색 유지

를 구현한다.

이를 통해 실제 코드에서도:

```text
사용자 보상 설정
→ 행동 결과 평가
→ 다음 Round 행동 선택 변화
```

라는 인과관계가 존재해야 한다.

미리 정해진 20개 장면을 순서대로 재생하는 방식은 사용하지 않는다.

---

## 25. 훈련 결과 보고서

20 Round가 끝나면 훈련 결과 보고서를 보여준다.

예:

```text
AI 훈련 결과

목표 도달률        높음
최고 도달 시간      36초
평균 시설 파손      6개
시민 위험           1회

행동 성향
빠른 해결 우선형
```

정확한 평가 지표와 표현 방식은 구현/테스트 단계에서 조정한다.

---

## 26. 훈련 완료 후 사용자 선택

훈련이 끝났다고 자동으로 실전에 투입하지 않는다.

사용자가 다음 중 하나를 선택한다.

### 다시 훈련
- 보상/벌점 설정 수정
- 새로운 20 Round 훈련 시작
- 이전과 다른 AI 행동 변화를 비교

### 실전 투입
- 현재 중앙 AI의 행동 성향을 실제 건물 작전에 적용

게임은 특정 보상 설정 하나를 정답으로 강요하지 않는다.

---

## 27. 실전 투입

실전에서는 연습 복제본 5대가 아니라 **실제 AI 대응 로봇 1대**만 투입한다.

사용자가 직접 로봇을 조종하지 않는다.

훈련을 통해 형성된 중앙 AI의 행동 경향을 바탕으로 로봇이 스스로 행동한다.

예:

### 속도 중심 AI
- 지름길 적극 사용
- 빠른 이동
- 시설물 파손 가능

### 안전 중심 AI
- 우회
- 시민 대피 기다림
- 느리지만 안전

훈련 단계의 보상 설계가 실전 행동에도 반영되어야 한다.

---

## 28. 실전 목표

실전 AI 로봇의 목표:

```text
건물 진입
↓
상층부 이동
↓
5층 중앙 보안실 도달
↓
점거된 시스템 복구
↓
출입 통제 시스템 정상화
↓
건물 탈환
```

악당과의 직접 전투는 강화학습의 핵심 gameplay로 만들지 않는다.

필요한 경우 악당 체포는 짧은 연출로 처리한다.

---

## 29. 실전 결과 보고서

실전 종료 후 결과를 보여준다.

예:

```text
건물 탈환 성공

작전 시간       47초
시설물 파손     3개
시민 위험       0회
```

향후 전체 게임 확장 시:

- 시설물 파손 → 배상
- 시민 안전 → 도시 평가
- 작전 보상 → 상점 / 업그레이드

등으로 연결할 수 있다.

경제 시스템은 현재 프로토타입에서는 제외한다.

---

# 30. 강화학습 Game State

전체 메인 State:

```text
INTRO
↓
BUILDING_CAPTURED
↓
SIMULATION_SETUP
↓
REWARD_SETTING
↓
TRAINING
↓
TRAINING_REPORT
├─ 다시 훈련 → REWARD_SETTING
└─ 실전 투입 → REAL_OPERATION
                    ↓
              OPERATION_REPORT
                    ↓
                 COMPLETE
```

---

## 30.1 INTRO

비지도학습 마지막 컷신에서 그대로 이어진다.

관제센터 경보와 중요 시설 점거 사실을 전달한다.

가이드:

> 악당들이 도시 교통 관제센터를 점거했어!  
> 하지만 바로 AI를 보내면 시민과 시설이 위험할 수 있어.  
> 먼저 똑같은 가상 건물을 만들어 연습시키자!

전이:

```text
INTRO
→ BUILDING_CAPTURED
```

---

## 30.2 BUILDING_CAPTURED

여러 CCTV 장면을 이용해 건물 점거 상황을 보여준다.

예:

```text
건물 외부 CCTV
↓
악당 집결

로비 CCTV
↓
출입구 장악

3층 CCTV
↓
내부 이동

5층 CCTV
↓
중앙 보안실 점거
```

목표:

> AI 대응 로봇을 중앙 보안실까지 보내 시스템을 복구한다.

전이:

```text
BUILDING_CAPTURED
→ SIMULATION_SETUP
```

---

## 30.3 SIMULATION_SETUP

실제 5층 건물을 홀로그램 훈련 공간에 복제한다.

준비:

- 건물 구조
- 장애물
- 시민
- 목표 위치
- 중앙 AI
- 병렬 연습 로봇 5대
- 카메라 / Overview

전이:

```text
SIMULATION_SETUP
→ REWARD_SETTING
```

---

## 30.4 REWARD_SETTING

사용자가 네 가지 보상/벌점 중요도를 설정한다.

```text
목표 도달
빠른 해결
시설물 파손
시민 위험
```

각각:

```text
신경 안 씀
조금 중요
중요
매우 중요
```

설정 완료:

```text
REWARD_SETTING
→ TRAINING
```

---

## 30.5 TRAINING

20 Round 전체를 관리하는 메인 훈련 State이다.

내부 서브 상태:

```text
ROUND_PREPARE
↓
ROUND_RUNNING
↓
ROUND_EVALUATION
↓
POLICY_UPDATE
↓
다음 Round
```

필요할 때:

```text
MICRO_EVENT
REPLAY
```

가 오버레이/서브 상태로 열린다.

---

## 30.6 ROUND_PREPARE

각 Round 시작 전:

- 현재 중앙 AI 행동 선택 경향 불러오기
- 5개 복제본에 행동 시나리오 배정
- 위치 초기화
- Round 카운트 증가

전이:

```text
ROUND_PREPARE
→ ROUND_RUNNING
```

---

## 30.7 ROUND_RUNNING

5개 연습 로봇이 같은 홀로그램 건물에서 동시에 행동한다.

사용자:
- 원하는 로봇 Follow
- AUTO 시점
- Overview
- 이벤트 알림 확인
- Replay 선택

각 로봇의 Episode가 종료될 때까지 진행한다.

전이:

```text
ROUND_RUNNING
→ 5개 시도 모두 종료
→ ROUND_EVALUATION
```

---

## 30.8 ROUND_EVALUATION

5개 경험을 현재 보상/벌점 설정 기준으로 평가한다.

전이:

```text
ROUND_EVALUATION
→ POLICY_UPDATE
```

---

## 30.9 POLICY_UPDATE

평가 결과를 다음 Round의 행동 Pool/선택 확률에 반영한다.

다음 Round가 남으면:

```text
POLICY_UPDATE
→ ROUND_PREPARE
```

20 Round 완료:

```text
POLICY_UPDATE
→ TRAINING_REPORT
```

---

## 30.10 MICRO_EVENT

`ROUND_RUNNING` 중 중요한 사건을 강조하기 위한 서브 상태.

AUTO 상태에서는 자동 강조 가능.

FOLLOW_ROBOT 상태에서는 사용자 시점을 강제로 바꾸지 않고 알림만 제공한다.

---

## 30.11 REPLAY

사용자가 다른 로봇의 중요 이벤트 알림에서 `[보기]`를 선택하면 잠시 Replay를 보여준다.

Replay 종료 후 기존 View State로 복귀한다.

---

## 30.12 TRAINING_REPORT

20 Round 결과를 요약한다.

사용자 선택:

```text
다시 훈련
→ REWARD_SETTING

실전 투입
→ REAL_OPERATION
```

---

## 30.13 REAL_OPERATION

실제 대응 로봇 1대를 점거 건물에 투입한다.

사용자는 직접 조종하지 않는다.

훈련에서 형성된 행동 성향을 바탕으로 AI가 스스로 이동한다.

전이:

```text
REAL_OPERATION
→ 작전 종료
→ OPERATION_REPORT
```

---

## 30.14 OPERATION_REPORT

실전 결과를 보여준다.

예:

```text
작전 시간
시설물 파손
시민 위험
건물 복구 성공 여부
```

전이:

```text
OPERATION_REPORT
→ COMPLETE
```

---

## 30.15 COMPLETE

강화학습의 핵심 개념을 짧게 설명한다.

> AI는 여러 행동을 직접 시도하고, 좋은 결과에는 보상을 받고 위험한 행동에는 벌점을 받으면서 더 좋은 행동을 배웠어.  
> 이렇게 행동의 결과를 이용해서 배우는 방법을 **강화학습**이라고 해!

---

# 31. Training View State

```text
TrainingView

mode
- AUTO
- FOLLOW_ROBOT
- OVERVIEW

selectedRobotId
```

### AUTO
중요 이벤트를 시스템이 자동으로 Main View에 보여줄 수 있다.

### FOLLOW_ROBOT
사용자가 선택한 로봇 시점을 유지한다.
다른 이벤트가 발생해도 강제 전환하지 않는다.

### OVERVIEW
건물 전체에서 5대의 위치와 이동을 본다.

---

# 32. 중앙 AI Training State

초기 개념 구조:

```text
CentralAITraining

- totalExperienceCount
- rewardPreferences
- actionPreferences
- trainingHistory
```

# 33. 연습 로봇 State

TrainingRobot

# 34. State 설계 핵심 원칙

### 34.1 보상 설정이 실제 다음 행동에 영향을 줘야 함

미리 정해진 성공 애니메이션을 순서대로 보여주는 방식은 사용하지 않는다.

반드시:

```text
사용자 설정
→ 행동
→ 결과 평가
→ 다음 행동 선택 변화
```

가 실제 코드 구조에서 존재해야 한다.

### 34.2 5개 연습 로봇은 하나의 정책을 공유

각자 별개의 AI로 성장하지 않는다.

5개의 경험을 중앙 AI에 모아서 다음 Round의 공통 행동 선택 경향을 바꾼다.

### 34.3 사용자 카메라 선택을 존중

사용자가 특정 로봇을 Follow하면 다른 이벤트 때문에 강제 화면 전환하지 않는다.

### 34.4 실패도 학습 경험

실패를 단순 Game Over로 만들지 않는다.

높은 벌점을 받은 경험도 다음 행동을 바꾸는 데이터가 된다.

### 34.5 하나의 정답 AI를 강요하지 않음

빠른 AI, 안전한 AI 등 여러 행동 성향이 모두 유효할 수 있다.

# 37. 강화학습 설계 완료 상태

현재 강화학습은 다음 수준까지 설계가 완료되었다.

- 핵심 학습 목표
- 비지도학습에서 이어지는 스토리
- 점거 건물과 시민 설정
- 홀로그램 훈련 공간
- 5층 / 20~25개 이상 경로 구조
- 보상/벌점 4개
- 자유로운 보상 설계
- 이상한 보상 결과 허용
- 중앙 AI + 병렬 복제본 5대
- 20 Round / 총 100회 경험
- 동일 조건의 5개 병렬 Simulation Instance
- Main View / Status / Overview 합성 구조
- Action Template / 행동 Pool 방식
- 상황 + 보상 + 과거 평가 기반 행동 선택
- Episode 종료 조건
- Main View / Follow / Overview
- Micro Event / Replay
- Round 평가
- 중앙 행동 선택 경향 업데이트
- 훈련 결과 보고서
- 재훈련 / 실전 투입 선택
- 실제 대응 로봇 1대의 실전 작전
- 실전 결과 보고서
- 전체 Game State 및 서브 State

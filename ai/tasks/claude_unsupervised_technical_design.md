### C1. 다이얼 단계 → 가중치 매핑
- **PRD 트랙: N/A (PRD 확정 — 다이얼 대신 2개 선택).** 선택한 특징의 가중치는 1, 선택하지 않은 특징은 0이며 좌표축으로만 쓴다. 엔진은 `weights: Record<FeatureKey, number>`를 받도록 만들어 두면 이후 다이얼 방식으로 확장할 수 있다.
- concept_rules 트랙일 경우:
  - 문제: 3단계를 수치로 바꿔야 한다.
  - 선택지: (a) 0 / 0.5 / 1 (b) 0 / 1 / 3 (c) 0 / 1 / 2
  - 추천: (b). 가중 유클리드 거리 √Σ wᵢ(Δxᵢ)²에서 "많이 봄"의 효과가 눈에 띄어야 군집 변화가 보인다.
  - 영향: 27개 조합 중 서로 다른 분할의 수가 달라진다. 테스트로 확인한다.

### C2. 군집 알고리즘
- **문제:** 실제 clustering을 쓸지, 규칙으로 처리할지 정해야 한다. RULES §5에 따라 사용자 문서에 정직하게 명시해야 한다.
- **선택지:**
  - (a) 규칙 기반: 선택한 2특징의 범주값이 같으면 같은 군집
  - (b) k-means: k를 정해야 하고 초기값이 무작위라 seed를 고정해야 한다
  - (c) 응집형 계층 군집(single-linkage) + 거리 임계값
- **추천 [제안]:** (c).
  - 주민마다 내부 연속값(0~1)을 저작 데이터로 둔다. 화면 라벨("초식/잡식/육식")은 이 값을 구간으로 나눠 만든다.
  - 선택한 2축으로 정규화 좌표를 만들고, 거리 τ 이하인 점끼리 연결해 군집을 만든다.
  - 결정적이고(무작위 없음) k가 필요 없다. 코드는 수십 줄 수준이며 순수 함수로 테스트할 수 있다.
  - 실제 계층 군집 절차가 맞으므로 "실제 clustering(단순 계층 군집), ML 모델 학습은 아님"이라고 명시할 수 있다. **[추정]** 데이터를 범주값으로만 두면 결과가 (a)와 같아진다. 그래서 내부값을 연속값으로 두는 쪽을 권한다.
  - 좌표평면에서 같은 칸 안의 위치가 데이터에 따라 자연스럽게 흩어진다. 가짜 jitter가 필요 없다.
- **영향:** `sim/clusteringEngine.ts` 1개 파일과 테스트. 악당 여부(`isVillain`)는 엔진 입력에서 제외하고, 이를 테스트로 강제한다(비지도학습 원칙).

### C3. 군집 개수 k와 플랫폼 개수
- **문제:** k를 어떻게 정할지, 몇 개의 영역으로 보여줄지 정해야 한다.
- **PRD 트랙 추천 [제안]:**
  - k는 C2의 임계값 τ에서 자연스럽게 결정되며, 사전에 고정하지 않는다.
  - 데이터 저작 목표: 6개 특징 조합 모두에서 군집이 **3~5개**가 되도록 한다. 스토리보드 기준으로 정답 조합은 4개다.
  - "플랫폼"은 PRD의 **점선 타원 테두리**로 대체한다. 군집 수만큼 Phaser Graphics로 그리며, 구성원의 bounding ellipse에 여백을 더한 모양이다.
- concept_rules 트랙일 경우: 플랫폼 수 = 군집 수, 최대 6개로 제한한다(45~50명 기준 가독성).
- **영향:** 데이터 검증 테스트에 "모든 조합에서 군집 3~5개"를 불변식으로 넣는다.

### C4. 애매 영역 판정

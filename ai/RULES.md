# SWfestival AI Rules

## 1. 우선순위
1. 현재 사용자의 직접 지시
2. 확정된 Source of Truth 문서
3. 이 RULES.md
4. 작업별 Skill 문서
5. 기존 코드의 관례

충돌 시 상위 우선순위를 따른다.

## 2. 설계 변경
- 확정된 설계를 이유 없이 변경하지 않는다.
- 중요한 설계 변경은 반드시:
  `검토 → 사용자 승인 → 구현`
  순서로 진행한다.
- 미확정 사항을 임의로 확정하지 않는다.
- 구현 중 새로운 결정이 필요하면 먼저 보고한다.

## 3. 구현 범위
- 사용자가 요청한 범위만 구현한다.
- 요청받지 않은 기능을 "좋아 보인다"는 이유로 추가하지 않는다.
- 기존 구조를 불필요하게 재작성하지 않는다.
- 큰 리팩터링은 사전 승인을 받는다.

## 4. 프로젝트 고정 방향
- 대상: 초등학생
- 플랫폼: PC / 노트북 웹
- 화면: Landscape
- 그래픽: top-down 2.5D pixel art
- 기술 스택: React + TypeScript + Vite + Phaser 4 + Tiled
- 목표 성능: 일반 PC Chrome 계열 브라우저에서 핵심 플레이 60fps
- 모바일은 현재 프로토타입 범위에서 제외
- 실제 ML 모델 학습보다 교육 목적의 규칙 기반 Simulation을 사용

## 5. 정확성
- 실제 구현하지 않은 기능을 구현했다고 말하지 않는다.
- 실제 RL / clustering / ML 모델을 사용하지 않으면 그렇게 명시한다.
- 테스트하지 않은 내용을 테스트했다고 말하지 않는다.
- 추정과 확인된 사실을 구분한다.

## 6. 코드 품질
- TypeScript type safety를 유지한다.
- 명확한 책임 분리를 선호한다.
- React와 Phaser의 책임을 불필요하게 섞지 않는다.
- 게임 데이터와 게임 로직을 가능하면 분리한다.
- 디버그용 임시 코드는 명확히 표시한다.

## 7. 사용자 승인 Gate
다음은 사용자 승인 없이 변경하지 않는다.
- 기술 스택
- Game State 구조
- 핵심 UI 흐름
- 캐릭터/그래픽 규격
- Tile 규격
- 스테이지별 핵심 규칙
- 프로젝트 폴더 구조의 대규모 변경
- 데이터 포맷의 파괴적 변경
